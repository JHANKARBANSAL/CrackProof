1. PROJECT VISION & CORE ARCHITECTURE
================================================================================
CrackProof is a specialized technical interview evaluation platform designed for
campus & fresher tech recruitment across 6 core Computer Science subjects:
- Java
- Object-Oriented Programming (OOP)
- Database Management Systems (DBMS)
- Operating Systems (OS)
- Computer Networks (CN)
- Data Structures & Algorithms (DSA)

Key Architectural Pillars:
1. Speech-to-Text: Candidate speaks naturally (English or Hinglish code-switching),
   transcribed via local Whisper.
2. Dense Knowledge Base (RAG): 1,904 curated textbook/Wikipedia markdown chunks
   embedded into 768-dimensional vectors using local Ollama (`nomic-embed-text`).
3. Grounded Factual Passages: For any interview question, the EmbeddingRetriever
   retrieves top relevant chunks ([1], [2]) so the LLM evaluates against verified
   reference facts rather than hallucinating from parametric memory.
4. Specialized Evaluator LLM (QLoRA Fine-Tuned Qwen2.5-3B-Instruct):
   Fine-tuned on structured evaluation JSON conforming to `AnswerEvaluation` schema:
   - verdict: CORRECT | PARTIALLY_CORRECT | INCORRECT
   - correctness_score (0-10), depth_score (0-10)
   - correct_points, missing_core_concepts, deeper_concepts_to_probe, misconceptions
   - evidence: list of DepthEvidence (FUNDAMENTAL, REASONING, APPLICATION, EDGE_CASE)
   - citations: claim + source_number matching [1], [2]
   - reasoning: technical justification

2. PRE-FINE-TUNING ENGINEERING AUDITS & CRITICAL FIXES APPLIED
================================================================================
Before generating full datasets or training, rigorous engineering audits uncovered
several critical bugs in the codebase. All were systematically fixed and verified:

[FIX 1] Completion-Only Loss Masking (Supervised Token Masking)
- Problem: SFTTrainer in `train_qlora.py` and the Colab notebook previously
  supervised the entire sequence (System prompt + User prompt + Candidate answer
  + RAG text + Assistant JSON). The model was penalizing itself trying to predict
  the prompt tokens.
- Fix: Updated tokenization in both `train_qlora.py` and `CrackProof_QLoRA_FineTuning.ipynb`.
  Prompt tokens (system, user, question, candidate answer, RAG reference) are
  masked with label = -100.
  Only Assistant JSON tokens are supervised.
  Integrated `DataCollatorForSeq2Seq(..., label_pad_token_id=-100)`.
- Verified: Sample 0 has 565 tokens -> 299 prompt tokens masked (-100), exactly
  266 assistant tokens supervised. 0 prompt leakage.

[FIX 2] Dense Embedding Synchronization (1904 Chunks == 1904 Embeddings)
- Problem: `knowledge/chunks.json` had 1904 chunks, but `knowledge/embeddings.json`
  only had 1884 vectors. Because count mismatched, `grounding.py` permanently
  fell back to BM25 keyword search, disabling dense semantic search.
- Fix: Rebuilt `knowledge/embeddings.json` via Ollama nomic-embed-text.
  Chunk count (1904) == Embedding count (1904), 768 dimensions.
  Active retriever is now `EmbeddingRetriever`.
  Tested and verified on Java, OOP, DBMS, OS, CN, DSA.

[FIX 3] Deterministic Reproducibility & Seeds
- Problem: Random seeds were uninitialized, causing stochastic training variance.
- Fix: Configured `random.seed(42)`, `np.random.seed(42)`, `torch.manual_seed(42)`,
  `transformers.set_seed(42)` across `train_qlora.py` and notebook cells 6 & 10.
  Added `"seed": 42` and `"data_seed": 42` to TrainingArguments.

[FIX 4] Evaluator Output Schema Alignment
- Standardized `AnswerEvaluation` Pydantic model in `evaluator.py`.
- Required fields verified: `verdict`, `correctness_score`, `depth_score`,
  `correct_points`, `missing_core_concepts`, `deeper_concepts_to_probe`,
  `misconceptions`, `evidence` (DepthEvidence), `citations` (Citation), `reasoning`.
